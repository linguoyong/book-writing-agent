# 本地写作 Agent —— 需求与架构方案

> 版本 v0.1 · 状态：已确认，进入 P0 开发

## 1. 产品定位

面向长篇小说的本地写作工作台，三个核心能力：

1. **对话式写作**：Agent 能读稿、改稿、续写、查设定，写作过程可审阅。
2. **作品知识库**：角色、势力、物品、世界观、大纲、素材可维护，Agent 可随时读写。
3. **整本书导入**：TXT 解析 → 章节切分 → 逐章抽取 → 结构化入库 → 建立索引。

要解决的核心问题：通用 RAG 直接切块检索，搜不到小说设定。根因是结构化设定被当成普通文本切碎，缺少实体层与章节进度语义。

## 2. 界面结构（v0.3）

单栏对话 + 可收起的左右侧栏，专家、技能、知识库是独立整页。

| 区域 | 内容 |
|---|---|
| 顶部栏 | 左：侧栏开关、品牌、项目名；右：设置、右栏开关、最小化/最大化/关闭 |
| 左栏 | 新建会话；专家、技能管理、知识库三个入口；项目；历史会话 |
| 中栏 | 对话视图，或专家页 / 技能页 / 知识库页（由左栏入口切换） |
| 右栏 | Tab：文稿 / 知识库 / 文件 / 变更 / 侧问 |

主题：默认浅色（米白背景、白卡片、墨绿强调色），CSS 变量集中在 `:root`，预留 `[data-theme="dark"]`，后续在设置里切换。

### 2.1 侧栏交互

- 左右侧栏宽度均可拖拽（左 200–460px，右 280–480px）。
- 左右侧栏均可收起，收起后通过顶部栏按钮重新展开；右栏开关位于窗口控制按钮左侧。
- 左栏收起后，鼠标移到窗口左边缘会浮出左栏（覆盖式，移开自动隐藏），与 GPT 桌面端一致。
- 最简形态：左右栏都收起，只显示对话面板。
- 文稿不再占用左栏页签：点击文件树、知识库原文结果时，右栏自动展开并切到「文稿」。

### 2.2 专家、技能与写作风格

- **专家**是写作人设：具备简介、标签、写作风格 prompt 与工作流程正文，存放在项目 `experts/<id>.md`。
- 专家页是独立整页：卡片网格、搜索、当前专家标记、设为当前、对话创建。
- 输入框底部显示当前专家（专家选择器），点击跳到专家页切换。
- **技能**存放在 `skills/<name>/SKILL.md`，技能页展示已装技能、启用状态与路径，支持对话创建。
- 专家与技能都支持**对话创建**：进入对话视图后 Agent 会先提问确认定位，信息足够后调用
  `expert_write` / `skill_write` 写入文件，完成后回到对应页面即可看到。

### 2.3 @ 引用（设计，后续实现）

输入框输入 `@` 弹出候选面板，支持四类引用：

| 引用 | 作用 |
|---|---|
| `@文件` | 选择书稿文件，路径随消息发送，Agent 用读取工具打开 |
| `@角色` / `@势力` / `@物品` | 引用知识库实体，整卡注入上下文，显示出处 |
| `@章节` | 引用章节原文片段，用于续写与对照 |
| `@技能` | 显式激活某个技能，仅本次会话生效 |

实现约定：发送时附带 `references` 字段（类型、id、路径），后端组装上下文并在 UI 顶部显示引用条；未识别的引用不发送。

### 2.4 知识库页面（参考 Dify）

- **列表页**：八类知识库卡片（角色/势力/物品/地点/世界观/大纲/素材/风格），显示条目数与切片数，支持一键重建索引。
- **详情页**四个页签：
  - 文档：条目列表 + front-matter 与正文预览。
  - 切片：当前库的全部索引切片（标题、来源、章节、文本）。
  - 召回测试：检索参数面板 + 查询 + 命中结果（相关度分数、来源、片段）。
  - 设置：返回数量、最低相关度、检索模式（混合/关键词/向量）、关键词权重、章节上限；保存后作为默认参数写入 `kb/config.json`。

### 2.5 对话消息导航（设计，低优先级）

- 对话左侧显示一条细长导航条，每条用户消息对应一根短横线。
- 悬停显示该条消息的摘要浮层，点击滚动到对应消息并高亮。
- 消息数超过 8 条时出现，避免短对话干扰。

### 2.6 其他交互

- 侧问：独立 thread，只读检索，不污染主会话，结论可一键带入主对话。
- 变更审批：Agent 修改知识库或文稿产生 git diff，逐条 approve / reject。
- 上下文面板：显示本轮注入了哪些资料与来源章节。

## 3. 技术选型

| 层 | 选型 |
|---|---|
| 桌面壳 | Electron + electron-vite |
| 前端 | React 19 + TypeScript + Vite + Tailwind CSS + Zustand |
| 编辑器 | CodeMirror 6（Markdown） |
| 后端 | Python 3.13 + FastAPI + SSE 流式 |
| Agent | deepagents（LangGraph 底座） |
| 模型 | OpenAI 兼容统一层，多 Provider 可配；写作模型与抽取模型分开 |

| 全文检索 | SQLite FTS5 + jieba 分词 |

| 版本管理 | 每本书独立目录独立 git |

## 4. 数据布局

应用仓库（本仓库）只放程序代码。书稿数据独立存放，由用户选择目录。

```
<书稿项目>/
├─ book.json               书目元数据（标题、作者、进度指针等）
├─ manuscript/             当前写作的卷/章
│  └─ vol-01/ch-001.md
├─ chapters/               导入的原文（P1）
│  └─ 0001-第一章.md
├─ kb/
│  ├─ characters/          角色卡
│  ├─ factions/            势力卡
│  ├─ items/               物品卡
│  ├─ locations/           地点卡
│  ├─ world/               世界观条目
│  ├─ outline/             总纲、卷纲、章纲
│  ├─ materials/           素材（风景、人物、心理描写）
│  └─ styles/              写作风格卡
├─ .index/                 向量与检索索引（git 忽略，可重建）
└─ .git/                   该书稿的版本历史
```

原则：**Markdown 文件是唯一事实来源，索引是派生物，可随时重建。**

## 5. 知识库三层

### 5.1 档案层（Canon，结构化）

带 YAML front-matter 的 Markdown，字段固定。角色卡示例：

```markdown
---
id: char-lin
type: character
name: 林昭
aliases: [小林, 林师兄, 昭哥]
faction: faction-qingyun
status: alive
first_chapter: 1
tags: [主角, 剑修]
timeline:
  - chapter: 1
    state: { realm: 炼气三层, location: 青云山, mood: 隐忍 }
  - chapter: 48
    state: { realm: 筑基初期, location: 落霞城, mood: 决绝 }
    arc: 得知身世，与师门决裂
relationships:
  - target: char-su
    type: 同门
    note: 互相试探
---

## 外貌
## 性格
## 成长路线
## 备注
```

关键设计：**角色状态按章节版本化**。写作第 N 章时只注入 `chapter <= N` 的最新状态，避免剧透与状态错乱。势力、物品同理可带 `timeline`。

### 5.2 原文层（Evidence，RAG）

- 章节正文按章 / 场景切块，按段落与对白边界切分，保留 `chapter_id`、出场角色、地点、事件标签。
- 检索先做实体路由：命中角色 → 取档案卡 + 该角色出场章节片段，而不是全库盲搜。
- BM25 与向量结果用 RRF 融合，再按章节进度与实体过滤。

### 5.3 素材层（Material / Style）

- 风景、人物、心理描写片段，按场景类型、情绪、手法打标签。
- 写作风格卡：人称、句长、描写密度、口头禅、禁忌。
- 用途：写作时作为 few-shot 参考，可一键"收入素材库"。

## 6. 检索方案

1. **查询路由**：规则 + 轻量分类 → 档案检索 / 原文检索 / 素材检索 / 混合。
2. **档案检索**：精确键（name/alias/tag）+ FTS5，命中整卡注入。
3. **原文检索**：FTS5(jieba) + 向量，RRF 融合，元数据过滤（章节上限、实体、类型）。
4. **重排**：可选的 reranker（后续版本）。
5. **组装**：档案卡全文 + 片段 + 出处（章节号、文件路径），供 Agent 引用。

## 7. Agent 架构

- 基座：deepagents（planning / filesystem / subagents / skills / human-in-the-loop）。
- 文件后端指向当前书稿项目目录，Agent 直接读写 Markdown。
- 工具清单：

| 工具 | 作用 |
|---|---|
| `kb_search` | 三层混合检索，返回带出处的片段 |
| `kb_get` | 读取单个实体档案 |
| `kb_write` / `kb_patch` | 新增或局部修改知识库条目 |
| `manuscript_read` / `manuscript_write` | 读写当前章节 |
| `chapter_list` / `chapter_read` | 章节管理 |
| `git_status` / `git_diff` | 变更查看 |

- 上下文策略：不全量塞知识库。进度指针 + 检索 + 显式引用 + 本轮注入清单。
- 专家 / 技能：`skills/` 下的 SKILL.md，按需渐进加载；不同风格写手作为子 agent。
- 侧问：独立 thread_id + 独立 checkpoint，只读工具集。

## 8. 导入管线（P1）

1. **解析**：编码探测（UTF-8 / GBK）→ 章节规则识别（第X章/回/节、卷、序章、番外，规则可配）→ 清洗（页眉页脚、广告行、重复行、全半角、空行归一）。
2. **边界预览**：章节边界可视化，允许手动修正后再继续。
3. **落盘**：`chapters/0001-标题.md` + `book.json`。
4. **试抽取**：先跑 5–10 章，验收字段质量，再全量。
5. **逐章抽取**：后台队列、并发、断点续传、增量。Pydantic 约束输出：人物提及、新实体、状态变化、势力关系、地点、物品、事件摘要、伏笔。低置信度进待确认队列。
6. **实体归并**：别名 / 称谓合并，冲突人工确认后才并入 Canon。
7. **建索引**：章节 / 场景 chunk + BM25 + 向量 + 标签，输出导入报告。

## 10. 默认约定与风险

约定：

- 应用仓库与书稿仓库分离，书稿独立 `git init`。
- 向量索引放 `.index/` 并排除出版本控制。
- 嵌入默认关闭（仅 BM25 可用），设置中可启用本地 bge-m3 或 API。
- Agent 改动一律产生可审阅的 diff。

风险：

- 逐章抽取的成本与一致性，靠试抽取验收、断点与增量控制。
- 别名归并是质量瓶颈，必须保留人工确认环节。
- deepagents 版本变动，需锁版本并封装适配层。
- 百万字书的索引重建耗时，需后台任务与进度反馈。

## 11. P0′ 内核改造（已交付）

> 定位调整：从「小说写作工具」转为「通用桌面 Agent 内核 + 写作域包」。写作能力下沉为第一个域包，内核提供状态、记忆、装配与边界。

### 11.1 四层内核

| 层 | 实现 | 说明 |
|---|---|---|
| 状态 | `agent/checkpointer.py` | AsyncSqliteSaver，`thread_id = session_id`；历史由 checkpoint 驱动，不再手工拼消息 |
| 记忆 | `memory.py` | 用户 / 项目 / 长期三层文件 + 每日日志，显式写入 + 会话沉淀 |
| 装配 | `context.py` | 8 层装配 + 每层字符预算，产出可展示的注入清单 |
| 边界 | `domains/` | 域包持有工具与规则；写操作审批预留在 `interrupt_on` |

### 11.2 目录与数据

```
~/.book-agent/
├─ app.db                 # 业务表 + checkpoint 表
├─ memory/
│  ├─ USER.md            # 跨项目偏好（常驻）
│  ├─ MEMORY.md          # 长期记忆（按日期分节，带来源）
│  └─ YYYY-MM-DD.md      # 每日日志（追加）
└─ books/<书名>/AGENTS.md # 项目记忆（常驻，Agent 可编辑）
```

### 11.3 专家与技能

- **专家 = 人格**：`experts/<id>.md` 正文整份注入 system prompt（此前只注入一行 `prompt`）。frontmatter 增加 `max_turns`、`skills`。
- **技能 = 方法**：`skills/<slug>/SKILL.md` 通过 deepagents `skills=` 渐进披露——索引常驻，正文按需读取；技能名必须是 ASCII slug。
- **会话级专家**：`sessions.expert_id` 持久化，切换专家只影响当前会话，不再全局漂移。

### 11.4 记忆写入策略

- 显式：Agent 调用 `remember(text, scope)`，scope 为 `user` / `project` / `long`。
- 沉淀：右栏「上下文 → 把本会话沉淀到长期记忆」，抽取模型输出事实条目并标注来源会话。
- 去重：按前 80 字归一化比对；冲突不覆盖，新增并标注。
- 回忆：`recall_conversations` 对全量消息做 FTS5 检索，替代「把历史全塞进 prompt」。

### 11.5 升级注意

- 旧库自动迁移：`sessions.expert_id`、`sessions.domain`；消息表补建 FTS 索引。
- 新增依赖 `langgraph-checkpoint-sqlite`。
- 需重启后端进程以加载新内核；旧会话 `expert_id` 为空时回落到 `general`。
- 索引改为单实体增量：`KbIndex.reindex_entity`，写入不再全库重建。

## 12. P1′ 能力边界与引用（已交付）

### 12.1 写审批（HITL）

- **拦截**：deepagents `interrupt_on`，只拦 `kb_write` / `manuscript_write`；只读侧问会话不拦。
- **中断时**：计算 unified diff（新建 / 追加 / 覆盖分别处理），落 `approvals` 表，推 `approval` SSE 事件。
- **审批卡**：逐条 通过 / 拒绝（可填拒绝原因），支持「全部通过」；diff 按增删行着色。
- **恢复**：`POST /chat/approve` → `Command(resume={"decisions": [...]})`，沿用同一 checkpoint，工具随后真实执行。
- **约束**：pending 期间新消息被拒（避免并发改写同一 thread）；拒绝后模型被告知原因，不再重试同一调用。
- **未做**：`edit`（人工改参数后执行）与 `respond` 两种决策类型。

### 12.2 @ 引用

- **候选**：`GET /projects/{id}/reference-candidates?q=` 聚合八类实体、文稿、章节、技能。
- **注入**：`context.references` 层（6000 字预算）；实体整卡（front-matter + 正文），文件 / 章节 / 技能截断 4k，带 source。
- **前端**：输入 `@` 弹候选，回车选择；引用以 chip 展示、可移除；随消息发送并记入 message meta。

### 12.3 全局技能

- `CompositeBackend` 把 `~/.book-agent/skills` 挂到 `/global-skills`，与项目 `skills/` 一起作为 `skills=` 来源。
- 索引区分 `[项目]` / `[全局]`；同名技能后者覆盖前者（全局在前、项目在后 → 项目优先）。

### 12.4 验收

- 新建文件：审批前文件不存在 → 通过后写入；拒绝后仍不存在。
- 待审批期间新消息返回错误；审批记录 `approved` / `rejected` 落库。
- @ 引用：候选命中、`references` 层注入、模型按引用原文回答。
- 全局技能：模型 `read_file` 读取 `/global-skills` 并遵循技能内容。

## 13. 空间、轮次与引导（P0″，已交付）

### 13.1 空间（工作区）

- **概念**：空间 = 目录（`projects.path` 就是空间根目录），不再只是「数据库里的项目」。
- **左侧**：`空间` 分组显示名称、最近会话、会话数；下方 `会话` 只列当前空间。没有空间时点「新建会话」先要求创建/打开空间。
- **新建**：默认落点 `~/.book-agent/books/<slug>`，可用「浏览…」改到任意目录；目录即空间。
- **打开**：接入已有 `book.json` 目录；空目录则初始化为书稿空间（目录结构 + git）。
- **Electron**：新增 `dialog:pick-directory` IPC（preload `window.desktop.pickDirectory`）。

### 13.2 对话轮次

- 每轮 = 用户消息 + 执行过程 + 结论。
- 执行中：过程展开，头部显示「处理中 · 用时」。
- 完成后：过程折叠为「已完成 · 用时 · N 步」，只保留结论；点击展开完整步骤（工具名、状态、输入输出）。
- 结论取最后一个 assistant 文本，其余中间叙述归入过程。

### 13.3 查看变更

- 后端按轮收集写工具路径（`kb_write` / `manuscript_write`），生成本轮相对 HEAD 的 unified diff（未跟踪新文件也会生成），随 `done` 事件返回并写入消息 `meta.turn`。
- 轮次底部「查看变更 · N 个文件」→ 右栏「变更」页签显示本轮 diff，可一键切回「全部改动」。
- 历史轮次从消息 meta 恢复，刷新后仍可查看。

### 13.4 执行中引导（不打断）

- streaming 时输入框发送即「引导」：`POST /chat/steer`，消息入队并落库（`meta.steering`）。
- `SteeringMiddleware` 在每次模型调用前 drain 队列，以 `<steering>` 片段注入当前对话，不中断当前 run。
- 若引导晚于最后一次模型调用到达，当轮补一段跟进，避免留到无关的下一轮。
- 空闲时调用返回 409；待审批期间允许入队，恢复时消费。

### 13.5 默认落盘位置

```
~/.book-agent/
├─ config.json                 # 模型配置
├─ app.db                      # 会话 / 消息 / 审批 / checkpoint
├─ memory/                     # USER.md、MEMORY.md、YYYY-MM-DD.md
├─ skills/                     # 全局技能（挂到 /global-skills）

```

应用仓库只放代码；`.screenshots/`、`out/`、`node_modules/`、`.workbuddy/` 均在 gitignore。

## 15. 沙箱与权限（现状与计划）

### 15.1 现在的隔离到哪一步

| 能力 | 状态 |
|---|---|
| 工作区目录边界 | ✅ `FilesystemBackend(virtual_mode=True)` 拦截 `..`、`~`、越界绝对路径 |
| 敏感路径规则 | ✅ `.env` / `secrets/**` / 私钥默认 deny（见 15.4） |
| 通用文件写/改/删 | ✅ 先过路径规则，再走 HITL 审批（`/**` 兜底） |
| 知识库 / 文稿写入 | ✅ `kb_write` / `manuscript_write` 审批 + diff |
| 命令执行 | ⛔ 没有 shell 工具，不存在命令面 |
| 网络访问 | ⚠️ 仅模型/embedding 出站；Agent 无抓取工具 |
| 进程 / 容器隔离 | ❌ 无（与 WorkBuddy 同级别） |

### 15.2 WorkBuddy 是「每空间一个沙箱」吗

不是。本机 `settings.json` 的 `sandbox` 是一套**路径规则表**，不是容器：

- `orderedRules.file`：135 条 preset，按路径给出 `read / write / delete` 的 `allow / ask`（如 `~/.ssh/` 全部 ask，`~/.aws/` 读 allow、写 ask）。
- `orderedRules.command` / `orderedRules.network`：命令与网络各自一套规则，`networkDenyAllMigrated: true` 表示网络默认拒绝后按需放行。
- `extraAllowWrite`：给连接器单独放行的写入目录。

也就是说：**空间只是目录边界，隔离来自「路径规则 + 审批 + 命令/网络规则」，不是每个空间起一个 VM。**

### 15.3 我们需要什么

- 现在：不需要容器。**路径规则引擎**已交付（15.4）；后续把 `remember` 等固定写入点也收进规则体系。
- 引入 shell / 抓取工具时：必须同步上 P2 的**命令白名单 + 网络默认拒绝**，否则等于把主机交给模型。
- 容器化只在需要跑不可信依赖或多人共享机器时才有价值；单机写作场景成本高于收益，已确认不做。

### 15.4 路径规则引擎（已交付）

- **配置**：`config.sandbox.rules`，每条包含 `pattern / read / write / delete / note`；支持 glob，裸文件名（如 `.env`）自动匹配任意深度。
- **默认 7 条**：`.env`、`.env.*`、`secrets/**`、`*.pem`、`*.key`、`id_rsa*`（读/写/删全 deny）；`.git/config`（读 allow，写/删 deny）。
- **编译**：`compile_permissions()` → `FilesystemPermission` 列表；**声明顺序即优先级**（先匹配先生效），末尾追加 `/**` 写入审批兜底。
- **语义**：deepagents 只有 `read / write` 两类操作，delete 归入 write，所以一条规则的 write 与 delete 取更严格者；`ask` 映射为 HITL 中断。
- **实测**：`read_file /secrets/readme.md` 返回 `permission denied for read on /secrets/readme.md`；普通文稿写入仍需审批。
- **设置页**：模型设置 → 文件权限，可增删规则、逐项切换 `allow / ask / deny`，保存写回 `config.json`。

### 15.5 两种权限模式（已交付）

| 模式 | 行为 |
|---|---|
| **请求批准**（`ask`，默认） | `kb_write` / `manuscript_write` / `write_file` / `edit_file` / `delete` 都中断审批；规则里的 `ask` 也走审批 |
| **完全访问**（`auto`） | 跳过所有写审批，直接执行；**规则里的 `deny` 仍然生效**（`.env`、私钥、`secrets/**` 读写都被拒绝） |

- 会话级存储：`sessions.permission_mode`，输入框左下角切换，`PATCH /sessions/{id}` 持久化。
- 新会话默认取 `config.sandbox.default_mode`（设置页可改）。
- 自研写工具补了 deny 硬校验（`check_path`），避免完全访问绕过路径规则。
- 不做第三种「只读」：侧问本身已是只读工具集，普通对话没有这个需求。

## 16. Markdown 渲染（P0‴，已交付）

- 结论区与侧问共用 `<Markdown>`（`react-markdown` + `remark-gfm`）。
- 支持标题、列表、表格、代码块、引用、链接；表格横向滚动，长代码块横向滚动。
- 链接不默认导航（Electron 内跳转会顶掉应用），改走 `shell.openExternal`，仅放行 `http/https`。
- 不启用 `rehype-raw`：HTML 按文本处理，避免注入。
- 代价：渲染包体积从 1.9MB 增至 2.49MB（桌面端可接受）。

## 17. Electron 托管后端（P1，已交付）

- **启动**：应用 ready 时 spawn `server/.venv/.../python -m uvicorn app.main:app`，端口优先 8787；被占用则自动取空闲端口。
- **就绪**：主进程轮询 `/api/health`（最长 40s）；IPC `backend:info` 等到 `ready` 或 `error` 再返回，渲染层据此 `setApiBase(port)`，首次请求不会打到未监听端口。
- **退出**：`before-quit` → `taskkill /T /F` 结束进程树 → 清理 `~/.book-agent/backend.pid`。
- **异常**：后端意外退出自动重启（最多 3 次）；上次崩溃遗留的进程由 pid 文件在下次启动时清理。
- **安全**：服务只绑定 `127.0.0.1`；CORS 放开到 loopback（Electron 的 `file://` Origin 为 null）；CSP `connect-src` 允许 `127.0.0.1:*`。
- **未做**：electron-builder 打包与 `resources/server` 布局；代码已保留 `process.resourcesPath/server` 候选路径。
