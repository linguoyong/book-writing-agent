- 另用实际配置的远程模型执行合成测试稿的写入、选中改写、独立审稿，核对真实服务兼容性。
- 桌面使用独立数据目录启动，实际结束后端进程以验证恢复，再正常关闭窗口以验证清理；同时核对真实用户 PID 文件未被修改。

## 已修复问题

| 问题 | 修复后的行为 | 验证 |
|---|---|---|
| reviewer 配置未完整纳入保存和密钥遮罩，设置页无法单独配置审稿模型 | 三路模型可分别设置；审稿 API Key 与其它角色一致遮罩，保存遮罩值不会覆盖真实密钥 | 配置往返集成测试、设置界面保存 |
| 非法模型配置或上下文窗口可能返回 500 | 返回带字段位置的 422，保留原配置，错误不回显输入值 | 配置失败路径测试 |
| 首次检索在没有索引基线时返回空结果 | 首次查询自动构建文本索引，不要求先手动重建 | 真实新空间 HTTP 检索 |
| jieba 在上下文和独立查询中分词不一致，导致“旧剑”漏检 | 短中文查询在 FTS 无命中时按原文精确补查，继续遵守类型、章号和条数限制 | 中文词、类型和防剧透上限测试；界面保存后检索 |
| 切片列表带查询条件时，total 与实际结果不一致 | 列表和计数使用相同过滤条件 | 分页总数测试 |
| 并发新建章节分配到同一编号 | 章号分配和写入在项目锁内完成，通过统一文件入口写入 | 并发 HTTP 请求断言编号唯一 |
| 生成中的会话或有后台任务的空间可被删除 | 拒绝删除并返回 409，提示先停止或等待；主对话、侧问及导入/拆解/索引任务均纳入检查 | 慢响应期间删除会话/空间测试 |
| 删除会话/空间后留下重新生成的 checkpoint | 删除原 thread 及该会话的再生成 thread | 真实 checkpoint 数据库清理测试 |
| 不存在会话的聊天请求可能返回空的 200 SSE | 在启动事件流前返回 404 | HTTP 状态断言 |
| 字数缓存跨天、同大小快速编辑、目标字数变更时可能不刷新 | 缓存签名包含日期、元数据及文件大小/纳秒修改时间 | 固定日期和同字节编辑回归 |
| 恢复中的对话追加引导后，会被旧轮询缓存覆盖；异步响应也可能追加到其它会话 | 成功引导后重启恢复轮询并作废旧响应，写入前核对当前会话 | store 回归、界面切页与引导实测 |
| 用户补充要求被折叠到执行步骤中，看起来像消失 | 用户补充常驻显示为“执行中补充”，主对话和侧问共用展示；工具步骤继续折叠 | 两种面板、生成中和历史状态的渲染回归及界面复查 |
| 桌面 PID 文件忽略 BOOK_AGENT_HOME，初次目录不存在也写不进去 | 生命周期文件使用隔离目录并创建父目录 | 单元测试和实际 Electron 启动 |
| 仅凭遗留 PID 清理进程，无法区分 PID 复用 | 保存并核验进程启动时间与命令行；旧版纯数字记录只清理文件 | 身份不符/相符/旧格式回归 |
| 开发启动优先使用旧冻结产物，修改源码后可能运行旧后端 | 开发态默认使用源码；安装版使用随包二进制，显式指定路径仍生效 | 开发/安装路径测试、实际启动参数 |
| 启动中崩溃重试可能被启动锁跳过，退出后定时器仍可重新拉起后端 | 启动等待共享 Promise，启动内恢复与运行后恢复分开处理；最多重启三次，退出取消重启且不再标记 ready | 12 项生命周期回归；真实进程崩溃、恢复和正常关窗 |

## 复现命令

在仓库根目录执行：

```powershell
pnpm check
uv run --directory server python -m unittest tests.test_application_integration -v
pnpm --filter desktop exec vitest run src/main/backend.test.ts
```

需要交互检查时，先运行 `pnpm build`，再启动隔离测试应用（不要填写真实数据目录）：

```powershell
uv run --directory server python -m tests.application_testbed --port 18879
```

程序会打印临时数据目录及地址，在浏览器打开该地址。该入口仅供测试，模型响应为模拟数据，验证完后 Ctrl+C 退出。
